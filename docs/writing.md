# 문서 작성 규칙

이 저장소의 문서와 GitHub 글(이슈·PR·릴리즈 노트·커밋 본문)을 쓰는 규칙. 저장소를 고치는 사람과 Claude Code가 함께 따름.

## 적용 범위

- 대상
  - `.md` 문서 전체(README, `docs/`, CHANGELOG)
  - GitHub Issue·PR의 본문과 댓글(이슈를 닫을 때 남기는 댓글 포함)
  - GitHub Release 노트
  - 커밋 메시지 본문
- 예외
  - Claude에게 주는 지침 문서([CLAUDE.md](../CLAUDE.md))는 명령형("~한다")을 씀.
  - 코드·식별자·명령어·파일명은 원문 그대로 씀.

## 문체

- 한국어 문장은 음슴체("~함", "~됨", "~임", "~필요")로 씀.
- "~했습니다", "~한다" 같은 문장형 종결은 쓰지 않음.
- 시점에 기대는 표현("지금은", "최근")은 날짜로 바꿔 씀.

## 목록 줄바꿈

- 목록 항목에서 주어(파일명·기능명 등)와 설명을 `—`나 `:`로 한 줄에 이어 쓰지 않음.
  - 주어를 본문 줄로 쓰고 설명은 그 아래 들여쓴 하위 항목으로 나눔.
  - 표 안에서는 하위 항목 대신 `<br>`로 줄을 나눔.
- 예외
  - "필드명: 값"을 나열하는 구조화된 기록은 값이 짧은 한 줄이면 그대로 둠.
  - 값에 문장이 여럿이거나 항목이 여러 개면 "필드명:"만 남기고 값을 하위 항목으로 나눔.

## 번호와 링크

- 이슈 번호(`#N`) 바로 뒤에 조사를 붙이지 않음. GitHub가 링크로 인식하지 못함.
  - `#24에서`는 `(#24)에서`처럼 괄호로 감싸거나 `#24 에서`처럼 번호 뒤를 띄워 씀.
- 파일·폴더 경로와 항목 ID는 클릭되는 링크로 씀. 코드 블록 안에서는 링크가 안 되므로 구조 목록은 표로 씀.
- 상대 경로 링크는 실제 파일을 가리켜야 함.

## markdown 형식

- 처음부터 markdownlint를 통과하게 씀.
  - 헤딩·목록 앞뒤에 빈 줄을 둠.
  - 표 구분선을 정렬하고 연속 빈 줄을 쓰지 않음.
  - 줄 길이(MD013)는 한국어 산문이라 검사하지 않음. 설정은 [.markdownlint.jsonc](../.markdownlint.jsonc)에 있음.
- 파일마다 역할이 하나임. 새 주제는 `docs/<주제>.md`를 만들고 README에는 링크 한 줄만 둠.
- 파일·함수·설정을 지우거나 이름을 바꾸면 그 이름을 `**/*.md`에서 찾아 같은 커밋에서 고침.

## 변경 이력과 이슈 글

- 변경 이력은 Keep a Changelog 형식을 따름.
  - `[Unreleased]`에 쌓고 헤더는 영문(Added·Changed·Fixed)으로 씀.
  - 이미 릴리즈된 `[X.Y.Z]` 섹션은 고치지 않음. 새 항목은 `[Unreleased]`에만 적음.
- 이슈·댓글 구성과 제목·라벨 규칙은 [작업 흐름](workflow.md#이슈-규칙)을 따름.
- 이슈를 닫을 때 남기는 댓글에는 커밋·변경 파일·검증 명령과 결과·미검증·영향을 적음.

## 무엇이 자동으로 검사되는가

| 규칙 | 검사 | 위치 |
| --- | --- | --- |
| markdown 형식 | markdownlint | CI([docs.yml](../.github/workflows/docs.yml)) |
| 상대 링크 | `check_links.py` | CI(docs.yml) |
| 릴리즈된 CHANGELOG 섹션 불변 | `check_changelog.py` | CI(docs.yml) |
| 회귀 테스트 개수와 문서의 개수 일치 | `check_test_count.py` | CI([vulnerability.yml](../.github/workflows/vulnerability.yml)) |
| 음슴체, 목록 줄바꿈, `#N` 뒤 조사 | 개인 설정의 형식 검사 훅 | 훅을 설치한 기기에서 이슈·댓글을 올릴 때만. CI는 검사하지 않음 |

- 문체와 목록 줄바꿈은 CI가 보지 못하므로 사람이 확인해야 함.
- 훅이 없는 기기에서는 이 문서를 기준으로 직접 점검함.
